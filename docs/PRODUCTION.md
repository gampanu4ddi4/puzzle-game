## 5. 사용자에게 요청할 검증 계획 — 아직 실행하지 않음

### 승인 단위

게임·코드 구현이 완료된 뒤에도 별도 요청 전에는 직접 테스트하지 않습니다. 실제 평가를 할 때는 **대상 빌드·구간·수집할 기록·실행 범위**를 먼저 제시합니다. 문서 검토, 엔진 실행, 자동 테스트, 실제 사람의 첫 플레이는 서로 다른 작업입니다.

예정 요청: “대표 구간 P01·P04·P07·P08을 처음 보는 사용자에게 평가하고, 해결 경로·정체 지점·공포/답답함 반응을 기록할까요?” 참가자 섭외나 메시지 발송은 별도 권한 없이 수행하지 않습니다.

### 첫 플레이 관찰

초기에는 서로 다른 숙련도의 처음 보는 사람 5명 정도를 모집하는 계획으로 시작합니다. 숫자는 통계적 대표성 보장이 아닙니다. 퍼즐 담당자가 해법을 설명한 뒤 ‘잘 된다’고 평가하지 않습니다. 생각을 말하게 하되 플레이 중 정답 질문을 던져 유도하지 않습니다. 참가자는 언제든 중단할 수 있습니다.

| 구간·시나리오 | 관찰할 질문 | 실패 신호 |
|---|---|---|
| P01 | 두 물건과 한 개체 가설을 비교하는가 | 끝까지 밀고 통과했지만 반응 관계를 설명 못 함 |
| P02 | 건넌 뒤 상태를 바꿀 계획을 세우는가 | 달리기·점프 타이밍을 연습함 |
| P03 | 사람이 닿는 거리와 케이블 길이를 구분하는가 | 더 세게 당기거나 숨은 연장선을 찾음 |
| P04 | 차단 상태를 보존 수단으로 이해하는가 | 무의미하게 세 밸브를 순회 |
| P05 | 입력 반응을 비교해 음원을 판단하는가 | 음량만 따라가거나 메뉴 이름을 찍음 |
| P06 | 표식으로 방향을 확인하고 운반을 예측하는가 | 잠수 자체가 해법이라고만 이해 |
| P07 | 현재·보관·반사를 각각 검증하는가 | 화면 번호 암기·글자 독해로만 해결 |

| P09 | 두 주소가 같은 방임을 회로로 확인하는가 | 방을 더 찾아 헤매거나 모든 버튼 반복 |
| P10 | 몸·배선의 조건을 함께 예측하는가 | 새 예외가 생겼다고 느끼거나 P08 절차만 반복 |
| P11 | 한 통과와 두 기록을 구분하는가 | 숨은 사람·숫자 암호·왕복 상쇄를 찾음 |

각 상황 뒤 정답 설명을 듣기 전에 “처음에는 무엇이라고 생각했고, 어떤 결과로 생각이 바뀌었나요?”를 묻습니다. 발견을 스스로 말할 수 있는지가 클리어 여부보다 중요한 자료입니다. 고정된 해법을 강요하지 않고 실제 대안 경로를 기록합니다.

### 공포와 답답함 분리

각 주요 구간 뒤 불안·호기심·답답함·통제감을 각각 0~4로 묻고 그 원인이 된 장면을 받습니다. 높은 불안 점수만 성공으로 보지 않습니다. 단서가 안 보이거나 조작이 불편해 생긴 답답함이면 공포 성과에서 제외합니다. 안전을 안 뒤에도 공간의 모순과 다음 발견을 궁금해하는지 확인합니다. 적 없는 공포를 즐기지 않는 사람의 반응을 취향 차이와 사용성 문제로 구분합니다.

초기 작업 가설은 다음과 같습니다. 검증된 수치가 아닙니다.

- 5명 중 4명 정도가 첫 발견을 자신의 말로 설명할 수 있는 방향을 목표로 합니다.
- 해법을 이해한 뒤 반복 실행·왕복이 길게 남으면 실패로 보고 줄입니다. 총 플레이타임을 채우기 위해 유지하지 않습니다.
- 한 번의 실험 결과가 두 가설을 구별하지 못하면 증거 자체를 다시 설계합니다.
- 후반부가 새 법칙 암기나 같은 해법의 반복으로 느껴지면 P09 축소·P10 배치 조정을 우선합니다.

### 추후 기능 확인 시나리오

별도 요청 시 확인할 목록입니다. 이번에 실행한 체크 결과가 아닙니다.

- 각 안정 상태의 저장/복원, 전환 중 저장 요청, 일회 큐 재생 방지.
- 현재 상황 초기화가 이전 완료·설정·흔적을 유지하는지.
- 판 위·다리 위·문 아래·접속 면 안에서 점유 보호가 동작하는지.
- P04 연결/차단의 모든 수위 상태, P08·P10 유지 해제 시 보류 상태, P11 시험/실기록 분리.
- 소리 끄기·색 구분 어려움·저품질·밝기·FOV·화면비·화면 효과 끄기에서도 같은 추론이 가능한지.
- 해법을 아는 사람이 달리기·점프·정확한 고개 각도·빠른 입력 없이 진행 가능한지.

## 6. 기록·배포·출시

후속 사용자 평가에서 필요한 기록은 상황 ID·새 증거·장치 입력·진전 없이 머문 시간·힌트 단계·초기화·완료 정도입니다. 로컬 파일을 기본으로 하고 계정·마이크·개인 대화·외부 텔레메트리를 수집하지 않습니다. 개인정보를 포함한 실제 플레이 녹화는 별도 동의를 전제로 합니다.

성능 목표는 대표 장면에서 측정한 뒤 갱신합니다. 기존 GTX 1060급·1080p 60 fps 목표를 달성한 것처럼 쓰지 않습니다. 외부 에셋·글꼴·음원 라이선스 목록은 실제 도입 때 작성합니다. Git LFS 전환·엔진 업데이트·상점 등록·가격·Steam 조건 확인은 이 문서 변경과 분리합니다.

상점 자료에는 ‘버튼을 누르는 장면’보다 정상적인 두 장소가 하나로 반응하는 짧은 비교를 사용합니다. 바이럴을 보장하거나 다른 게임의 캐릭터·브랜드·장면을 복제하지 않습니다. 홍보 가능한 장면은 실제 플레이가 재미있다는 검증을 통과한 뒤 선택합니다.
