# 제작 계획서 (2인 개발)

> 일정의 숫자는 **가정에 기반한 추정**이다. M1이 끝나면 실제 걸린 시간으로 전체를 다시 계산한다.

## 1. 역할 분담 (제안)

두 사람의 강점을 아직 모르므로, 가장 흔한 나눔을 기본으로 적는다. 맞지 않으면 바꾼다.

| | 사람 A (시스템) | 사람 B (공간) |
|---|---|---|
| 주 담당 | 프로그래밍, 세 규칙 시스템, 저장, 메뉴, 빌드 | 레벨 조형, 모델, 재질, 조명, 소리 |
| 함께 | 퍼즐 설계, 플레이 테스트, 그레이박스 제작 | 퍼즐 설계, 플레이 테스트, 그레이박스 제작 |
| 최종 결정권 | 기술, 조작감 | 화면, 소리, 분위기 |

- **퍼즐 설계는 둘이 함께 한다.** 한 사람이 만든 퍼즐을 다른 사람이 아무 설명 없이 풀어 보는 것이 가장 싼 테스트다.
- 의견이 갈리면 그 분야의 최종 결정권자가 정하고, 테스트 결과가 나오면 다시 본다.

## 2. 일하는 방식

- **주 1회 정기 회의 (30분):** 지난주에 한 것, 이번 주에 할 것, 막힌 것.
- **작업 관리:** GitHub Issues + Projects 보드 (할 일 / 하는 중 / 확인 필요 / 끝). 퍼즐 하나가 이슈 하나.
- **Git 규칙:**
  - `main`은 항상 실행되는 상태로 둔다.
  - 작업은 가지를 따서 하고(`p1-3-oneway`, `sys-water` 같은 이름), 끝나면 상대가 한 번 실행해 보고 합친다.
  - 모델, 텍스처, 소리는 Git LFS.
  - **장면 파일 하나는 한 번에 한 사람만** 고친다 (이슈에 담당자를 적는다).
- **퍼즐 하나의 완료 기준:**
  1. 레벨 명세대로 그레이박스가 동작한다
  2. 상대가 설명 없이 풀어 봤다
  3. 힌트 3단계가 연결됐다
  4. 방 다시 시작과 저장·불러오기가 동작한다
  5. 디버그 이동 메뉴(F1)에 등록됐다

## 3. 일정

**가정:** 두 사람이 각각 주 20시간씩 쓴다. 전업으로 하면 기간이 절반쯤 된다.

| 단계 | 기간 | 내용 | 끝났다는 기준 |
|---|---|---|---|
| M0 준비 | 2주 | 저장소, Godot 프로젝트, 플레이어 조작, 문, 그레이박스 규격 | 빈 방을 걸어 다니고 문을 열 수 있다 |
| M1 1장 그레이박스 | 6주 | R1 시스템, 프롤로그, 1-1~1-8, 디버그 도구 | 1장을 처음부터 끝까지 플레이 |
| M2 1장 완성판 | 6주 | 주차장 아트, 소리, 화면 효과, 힌트, 저장, 구역 불러오기 | **외부 테스트 1차** (3~5명) |
| M3 2장 그레이박스 | 8주 | R2 시스템, 사이 A, 2-1~2-9 | 프롤로그부터 2장 끝까지 이어서 플레이 |
| M4 3장 그레이박스 | 10주 | R3 시스템, 사이 B, 3-1~3-10 | 3장 끝까지 이어서 플레이 |
| M5 4장 그레이박스 | 6주 | 4-1~4-6, 에필로그, 흔적 12개 배치 | **외부 테스트 2차**: 전체 통플레이 (5명 이상) |
| M6 전체 아트와 소리 | 14주 | 2~4장 아트, 조명 굽기, 소리, 메뉴, 설정, 접근성 | 모든 장이 최종 모습 |
| M7 다듬기 | 6주 | **외부 테스트 3차**, 힌트 조정, 최적화, 버그 | 치명적인 버그 0개, 성공 기준(GDD 12장) 충족 |
| M8 출시 준비 | 4주 | 상점 페이지, 예고 영상, 도전 과제, 빌드 심사 | 출시 |

**나란히 진행하는 일**
- 그레이박스 단계(M3~M5) 동안 B는 **확정된 이전 장의 아트**를 먼저 시작한다. 그래서 M6의 14주는 남은 분량이다.
- A는 M6 동안 메뉴, 설정, 접근성, 컨트롤러, Steam 연동을 한다.
- **상점 페이지는 M2가 끝나면 바로 연다** (찜 목록을 일찍 모으기 위해). 8장 참고.

**첫 4주에 할 일 (구체적으로)**

| 주 | A | B |
|---|---|---|
| 1 | 저장소 정리, Godot 프로젝트 생성, `.gitignore`, LFS, 입력 설정, 플레이어 걷기와 시점 | 그레이박스용 기본 부품(바닥, 벽, 기둥, 경사로) 격자에 맞춰 제작, 주차장 한 층 조립 |
| 2 | 상호작용 광선, 문, 웅크리기, 점프. 프롤로그 동선 걷기 | 프롤로그 그레이박스, 임시 조명, 임시 화살표와 번호판 |
| 3 | `LoopGate` 구현, 1-1에서 옮김이 티 나지 않는지 확인 | 1-1, 1-2 그레이박스 |
| 4 | 디버그 도구 F1~F3, `PuzzleRoom` 틀 | 1-3, 1-4 그레이박스. 서로 만든 퍼즐 풀어 보기 |

## 4. 플레이 테스트

### 언제, 누구에게
| 차수 | 시점 | 인원 | 보는 것 |
|---|---|---|---|
| 내부 | 매주 | 서로 | 상대가 만든 퍼즐을 설명 없이 풀기 |
| 1차 | M2 끝 | 3~5명 (지인) | 1장: 규칙을 스스로 발견하는가, 분위기 |
| 2차 | M5 끝 | 5명 이상 (퍼즐 게임을 하는 사람 포함) | 전체: 막히는 곳, 지루한 곳, 총 시간 |
| 3차 | M7 | 8명 이상 (처음 보는 사람) | 힌트 타이밍, 버그, 성공 기준 |

- 한 번 플레이한 사람은 같은 구간의 테스터로 다시 쓸 수 없다. **테스터를 아껴 쓴다.**

### 진행 방법
1. 아무 설명 없이 시작하게 한다. "생각나는 걸 소리 내어 말해 주세요"만 부탁한다.
2. 막혀도 돕지 않는다. 20분이 지나면 그 퍼즐만 건너뛰게 한다.
3. 옆에서 기록한다: 막힌 곳, 말한 것, 표정이 바뀐 순간.
4. 끝나면 묻는다.
   - 이 장소의 규칙을 한 문장으로 말해 주세요. (규칙이 전달됐는지)
   - 가장 기억에 남는 순간은? 가장 답답했던 순간은?
   - 무서웠나요? 어떤 느낌이었나요?
   - 그만두고 싶었던 때가 있었나요? 언제요?

### 자동 기록
디버그의 플레이 기록 기능이 퍼즐마다 다음을 파일로 남긴다: 걸린 시간, 힌트가 몇 단계까지 나왔는지, 방을 다시 시작한 횟수. 테스트가 끝나면 표로 모아 아래 기준으로 본다.

| 신호 | 조치 |
|---|---|
| 한 퍼즐의 중간값이 계획 시간의 2배 이상 | 단서를 강화하거나 단순화 |
| 힌트 3단계까지 간 사람이 30% 이상 | 퍼즐을 다시 설계 |
| 계획 시간의 절반 이하로 다들 풂 | 그대로 두되, 뒤 퍼즐과 합칠지 검토 |
| 규칙을 한 문장으로 말하지 못함 | 장의 첫 두 퍼즐을 고친다 |

## 5. 줄일 수 있는 것 (우선순위 순)

일정이 밀리면 위에서부터 뺀다. 빼도 전체 흐름이 유지되는 것들이다.

| 순서 | 대상 | 빼면 |
|---|---|---|
| 1 | 흔적 12개의 숨은 결말 장면 | 흔적은 남기고 결말 변화만 뺀다 |
| 2 | 1-7 반 층 | 엘리베이터 홀 문을 열어 둔다 |
| 3 | 2-3 유아풀 | 통로로 바꾼다 |
| 4 | 3-4 의자 | 교실을 그냥 지나가게 한다 |
| 5 | 3-9 도서관 | 3-8에서 바로 3-10으로 |
| 6 | 4-5의 3단계 (카메라) | 두 단계로 줄인다 |
| 7 | 사이 B의 B-1 샤워실 | 배수로가 탈의실로 바로 이어진다 |
| 8 | 컨트롤러 지원 | 출시 후 추가 |

**빼면 안 되는 것:** 각 장의 첫 두 퍼즐(규칙의 발견), 2-7 다이빙 타워, 3-6 고르기, 4-6 출구, 사이 구간의 "스며듦" 연출.

## 8. Steam 출시 준비

> 아래 조건은 바뀔 수 있다. **등록 전에 Steamworks 공식 문서에서 다시 확인한다.**

| 할 일 | 시점 | 메모 |
|---|---|---|
| Steamworks 가입, 세금·은행 정보 입력, 등록비 결제 | M2 중 | 결제 후 출시까지 기다려야 하는 기간이 있다 (30일로 알려져 있음) |
| 상점 페이지 작성: 소개글, 스크린샷 5장 이상, 캡슐 이미지 | M2 끝 | 1장 완성판 화면으로 만든다 |
| "출시 예정" 페이지 공개 | M2 끝~M3 | 출시 전 최소 2주는 공개되어 있어야 한다고 알려져 있음. 실제로는 훨씬 일찍 연다 |
| 예고 영상 (30~60초) | M3, M7에 갱신 | 규칙을 설명하지 말고 "어?" 하는 순간을 보여준다 |
| 체험판 | M5~M6 | 프롤로그 + 1장. Steam 넥스트 페스트 참가를 검토 |
| 도전 과제 | M7 | 장 클리어 4개, 흔적 12개, 숨은 결말, 힌트 없이 클리어 등 약 20개 |
| 클라우드 저장 | M7 | `user://`의 저장 파일을 지정 |
| 빌드 심사 제출 | M8 첫 주 | 심사에 며칠이 걸리므로 여유를 둔다 |
| 가격 | M8 | 비슷한 분량의 인디 퍼즐 게임 가격대를 조사해서 정한다 |

**상점 소개의 핵심 문장 (초안)**
> 문 닫은 복합센터. 주차장은 되돌아가야 나아가고, 수영장은 같은 타일끼리 이어지고, 학교는 보지 않을 때 바뀐다. 아무도 없다. 규칙만 있다.
